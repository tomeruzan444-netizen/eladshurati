# מעבר מ‑Cloudways ל‑Vercel — תוכנית ביצוע

מטרה: אותו דומיין, אותן כתובות URL, אותו תוכן, אותה מטא‑דאטה. משתנה רק העיצוב.

---

## 1. הממצא שמשנה את כל התמונה

**ה‑DNS לא יושב ב‑Cloudways — הוא יושב ב‑Cloudflare.**

```
nameservers : cameron.ns.cloudflare.com / sandra.ns.cloudflare.com
A records   : 104.21.59.237 , 172.67.185.111   (כתובות של Cloudflare, כלומר proxy דלוק)
www         : מצביע לאותו מקום
```

זה אומר שהמעבר הוא **שינוי רשומה אחת בפאנל של Cloudflare** — לא העברת דומיין, לא שינוי nameservers אצל הרשם, ולא נגיעה ב‑Cloudways.
המשמעות המעשית: המעבר לוקח דקות, וה‑rollback לוקח דקה.

## 2. מה כבר תוקן והועלה (בוצע)

| מה | למה זה קריטי |
|---|---|
| `sitemap_index.xml` + `page-sitemap.xml` + `post-sitemap.xml` + `category-sitemap.xml` | Search Console מושך את הכתובות האלה כבר שנים. קודם ייצרנו רק `sitemap.xml` שטוח. הכתובות בפנים **זהות בייט‑לבייט** למה שהאתר החי מפרסם (כולל אותיות קטנות ב‑percent‑encoding). |
| `robots.txt` אמיתי | משחזר את הכללים החיים, כולל הבלוקים הייעודיים ל‑`OAI-SearchBot`, `ChatGPT-User` ו‑`GPTBot` — אלה מה שמביא ציטוטים בתשובות AI. |
| Rewrite של `/wp-content/uploads/*` → `/assets/images/*` | ה‑`og:image` וה‑JSON‑LD שומרים בכוונה את כתובות התמונות המקוריות. בלי זה כל תצוגה מקדימה בשיתוף ברשתות וכל תוצאה ב‑Google Images היו נשברות. נבדק בפועל על Vercel: מחזיר 200. |
| הפניות ישנות | `/index.php` → `/` (308), `/feed` , `/wp-login.php` , `/wp-admin/*` |
| תג `google-site-verification` | היה על כל 63 העמודים החיים ואצלנו נעלם. בלי זה הנכס ב‑Search Console מאבד אימות בדיוק ברגע שצריך אותו כדי לעקוב אחרי המעבר. |
| טופס לידים עובד (`api/lead.js`) | היה `action="#"`. עכשיו שולח מייל כמו וורדפרס. חסר רק מפתח API — ראה 3.1. |
| סקריפט בדיקה `scripts/8-golive.mjs` | סורק את כל 63 הכתובות, ה‑sitemaps, robots, תג האימות, תמונות ישנות והטופס. מריצים לפני ואחרי המעבר. |
| הצמדת noindex לדומיין האמיתי בלבד | **זו הייתה תקלה שהייתה הורסת את המעבר:** `STAGING=1` קבוע בפקודת הבנייה של Vercel, ו‑`render.mjs` הטביע `noindex, nofollow` על כל עמוד כשהדגל דלוק. עלייה לאוויר כמו שהיה = הסרה מהאינדקס של אתר מדורג. עכשיו גם המטא וגם `robots.txt` קוראים החלטה אחת משותפת, והיא נפתחת רק כשהדומיין האמיתי מחובר. |

בדיקות שעברו: 63 עמודים, 3561 קישורים פנימיים — 0 שבורים, 281 תמונות — 0 חסרות, והשוואה מול הבנייה הקודמת מראה שינוי ב‑`<head>` בלבד, **0 שינויים בתוכן הנראה**.

## 3. חוסמים — לטפל *לפני* שנוגעים ב‑DNS

### 3.1 טופס יצירת הקשר — נבנה, נשאר להזין מפתח

הטופס באתר החדש היה `action="#"`, כלומר כל ליד היה נעלם בשקט. נבנה מטפל ב‑`api/lead.js`
שמשחזר בדיוק את ההתנהגות של וורדפרס — אותו נמען, אותו עותק, אותה שורת נושא:

```
נמען  : eladshurati131@gmail.com      (משתנה LEAD_TO)
עותק  : webpress2022@gmail.com        (משתנה LEAD_CC)
נושא  : פנייה מהאתר- אלעד- יועץ ופיתוח עסקי
```

הטופס עובד גם בלי JavaScript. במקום reCAPTCHA — honeypot ובדיקת זמן מילוי, כדי לא
לטעון סקריפט צד־שלישי בכל עמוד. אם תופיע ספאם אמיתי, Cloudflare Turnstile נכנס
בלי לגעת ב‑HTML.

**מה שנשאר לעשות (5 דקות):**
1. לפתוח חשבון ב‑[resend.com](https://resend.com) — חינם עד 3,000 מיילים בחודש.
2. לאמת את הדומיין `elad-digital.co.il` אצלם. הם ייתנו רשומות DNS —
   מוסיפים אותן ב‑Cloudflare, שם אנחנו עובדים ממילא.
3. ב‑Vercel → Settings → Environment Variables להוסיף:
   ```
   RESEND_API_KEY = re_xxxxxxxx
   LEAD_FROM      = אלעד שורתי <hello@elad-digital.co.il>
   LEAD_CC        = webpress2022@gmail.com
   ```
4. לפרוס מחדש ולהריץ `node scripts/8-golive.mjs <url> --send` — זה שולח פנייה
   אמיתית, כך שתיבת הדואר מוכיחה שהמסלול עובד מקצה לקצה.

בלי המפתח, המטפל מחזיר 503 ורושם ללוג במקום לדווח על הצלחה שלא קרתה.

**נקודה למחשבה:** באתר החי הטופס יושב בסיידבר של 62 עמודים; אצלנו הוא ב‑4
(בית, שאלות ותשובות, פרוייקטים, צרו קשר). בכל 63 העמודים יש CTA, קישור לעמוד
צרו קשר וקישור וואטסאפ — אז מסלול המרה קיים בכל מקום. אם תרצה טופס בכל עמוד
כמו קודם, זה שינוי קטן.

### 3.2 רכיבים שקיימים באתר החי וחסרים אצלנו

| כפתור צ'אט צף (Chaty) | 63/63 עמודים | ערוץ לידים פעיל. אצלנו יש קישורי טלפון/וואטסאפ בעמוד, אבל לא כפתור צף. |

### 3.3 סביבת Vercel

- יש **שני פרויקטים** על אותו ריפו. למחוק/לשנות שם לאחד, כדי שלא תהיה אי‑בהירות לאיזה פרויקט מוצמד הדומיין.
- לכבות Deployment Protection על production.

## 4. סדר הפעולות

### שלב 0 — הכנה (בלי שום השפעה על האתר החי)
1. לתקן את הטופס (3.1) ולהחזיר את ווידג'ט הנגישות והכפתור הצף (3.2).
2. לסדר את פרויקטי Vercel, לכבות Deployment Protection.
3. להצמיד `elad-digital.co.il` **וגם** `www.elad-digital.co.il` לפרויקט הנכון ב‑Vercel ולהשלים אימות.
4. ב‑Cloudflare: להוריד TTL של הרשומות ל‑5 דקות. (רלוונטי רק אם ה‑proxy כבוי; ברשומה מ‑proxy השינוי מיידי ממילא.)
5. להריץ סריקה מלאה של 63 הכתובות מול ה‑preview ולוודא 200 על כל אחת.

### שלב 1 — המעבר עצמו
6. ב‑Cloudflare, להפנות את הרשומות ל‑Vercel. ההמלצה שלי: **לכבות את ה‑proxy (ענן אפור) ולהצביע ל‑Vercel ישירות** — `CNAME → cname.vercel-dns.com` (או `A → 76.76.21.21`).
   הסיבה: Vercel הוא כבר CDN גלובלי. שכבת Cloudflare מעליו מוסיפה עוד נקודת כשל ועוד cache לנקות, בלי תמורה. Cloudflare נשאר ספק ה‑DNS.
   *(אם רוצים לשמור את ה‑proxy דלוק — חובה SSL mode “Full (strict)”, אחרת נופלים ללולאת הפניות.)*
7. להמתין להנפקת תעודת SSL אצל Vercel (בדרך כלל דקות).
8. להריץ שוב את סריקת 63 הכתובות — הפעם מול הדומיין האמיתי.

### שלב 2 — אחרי
9. ב‑Search Console: לוודא שהאימות מחזיק, ולבקש fetch מחדש של `sitemap_index.xml`.
10. **להשאיר את Cloudways דלוק 2–4 שבועות** כרשת ביטחון.
11. לעקוב אחרי Coverage ו‑Core Web Vitals ב‑Search Console.

### Rollback
להחזיר את הרשומה ב‑Cloudflare למצב הקודם. זמן חזרה: דקות. זו הסיבה שלא מכבים את Cloudways מיד.

## 5. פגמים שקיימים באתר החי ולא נגענו בהם

מדיניות התוכן היא 1:1 מדויק, אז השארנו אותם כמו שהם. כולם מועמדים ל"תיקון תקלה":

- `/פרוייקטים/` — ה‑meta description הוא פשוט כתובת של קובץ mp4 (`odem-final.mp4`). זה מה שגוגל מציג בתוצאות.
- `/פיתוח-עסקי/` — פסקת lorem ipsum.
- `/volume_up/` — slug זבל שמתפרסם ב‑sitemap.
- 2 עמודים בלי meta description, 2 כותרות כפולות, תיאור כפול אחד, 8 כותרות מעל 65 תווים.
- 20 תמונות עם `alt` ריק.
- ב‑JSON‑LD של עמוד הבית התמונה הראשית היא לוגו placeholder (`6.png`), ואין `og:image` לעמוד הבית.

## 6. שווה לשקול

**אין באתר שום מדידה.** אין GA4, אין GTM, אין פיקסל. אחרי המעבר לא תהיה שום דרך לראות מה קרה לתנועה — חוץ מ‑Search Console, שמראה קליקים והופעות בלבד.
ההמלצה: להתקין GA4 **על האתר החי, לפני המעבר**, ולתת לו שבוע‑שבועיים לאסוף בסיס להשוואה.
